Motor de Preparació de Comandes de Venda — variant SAP

Versió 1 — Juliol 2026
Plataforma objectiu: Ubuntu Server (servidor ae01farwebsrv, ja operatiu amb l'app Kais)
Aplicació web Python/Flask amb connexió a SQL Server (SAP B1) + Service Layer REST
Punt de partida: L'aplicació SAP ja està desplegada de forma experimental al servidor ae01farwebsrv amb el servidor de desenvolupament de Flask (port 5002, servei comandes-venda-sap.service). Aquesta guia descriu els passos addicionals per portar-la a producció: substituir el dev server per Gunicorn + Apache com a proxy invers (mateix pattern que l'app Kais al mateix host).

0. Estratègia URL

L'app SAP hereta la URL històrica comandes.agrienergia.local que actualment serveix Kais. Els usuaris no han de canviar cap enllaç ni favorit.

Kais es rebateja a comandes-kais.agrienergia.local i queda com a fallback per si cal marxa enrere ràpida (rollback en < 5 min). Kais continua actiu al port 5001 fins novembre 2026 (segons acord operatiu).

URLAbans del swapDesprés del swap
comandes.agrienergia.localKais (port 5001)SAP (port 5002)
comandes-kais.agrienergia.local—Kais (port 5001, fallback)
192.168.11.244:5002 (IP directa)SAP (dev server)SAP (Gunicorn, fallback tècnic)
Runbook del swap: el procediment operacional detallat del canvi (Fase A preparació, Fase B swap, Fase C verificació, i rollback) es troba a docs/runbook_swap_url_produccio.md al repo. Aquesta guia HTML descriu l'arquitectura; el runbook descriu els passos exactes al servidor durant el canvi.

1. Context i estat inicial

Estat actual al servidor

El servidor ae01farwebsrv (192.168.11.244) ja allotja l'app Kais en producció (port 5001, /var/www/comandes-venda) i la variant SAP en mode experimental (port 5002, /var/www/comandes-venda-sap). La variant SAP corre actualment amb el servidor de desenvolupament de Flask, que no és apte per producció.

Punt de consumidor

L'endpoint principal de l'aplicació SAP és POST /api/afegir-palets/<DocEntry>. El botó "Calcular embalatges" del formulari Sales Order de SAP (configurat via B1UP a la Function Button FB-004, línia "Calcular embalatges" → UF-038 amb Codi Dinàmic .NET) fa la crida HTTP a aquest endpoint.

Coexistència amb Kais: Les dues apps són independents. Kais llegeix la BD del sistema antic; SAP llegeix i escriu a SAP Business One via Service Layer. Kais continua actiu al port 5001 fins novembre 2026, servit ara a comandes-kais.agrienergia.local (vegeu secció 0). L'únic moment sensible és la finestra del swap Apache (~30 s), en la qual el ServerName de Kais canvia; durant aquest interval s'afegeix un ServerAlias temporal per no dropar peticions in-flight.

        │
        │  Executa RF1-RF14, valida, genera línies palet
        ▼
    ┌──────────────────────┬────────────────────────┐
    │                      │                        │
SQL Server SAP B1        Service Layer SAP B1
AE01SAPSQL.Agrienergia    https://192.168.11.238:50000

Diferència principal amb Kais: l'app SAP escriu a la BD (afegeix línies palet a la comanda) via el Service Layer REST, no directament al SQL Server. La connexió SQL Server és només de lectura (ApplicationIntent=ReadOnly).

3. Substituir dev server per Gunicorn

3.1 Instal·lar Gunicorn al venv de SAP

cd /var/www/comandes-venda-sap
sudo -u www-data venv/bin/pip install gunicorn

3.2 Aturar el servei actual (dev server)

sudo systemctl stop comandes-venda-sap

3.3 Modificar el servei systemd

Substituir la línia ExecStart del fitxer del servei per la crida a Gunicorn:

sudo nano /etc/systemd/system/comandes-venda-sap.service

Contingut resultant:

[Unit]
Description=Motor Preparació Comandes Venda (variant SAP)
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/var/www/comandes-venda-sap
Environment=KAIS_APP_PATH=/var/www/comandes-venda
Environment=PORT=5002
EnvironmentFile=/var/www/comandes-venda-sap/.env
ExecStart=/var/www/comandes-venda-sap/venv/bin/gunicorn \
    --bind 127.0.0.1:5002 \
    --worker-class gthread \
    --workers 2 \
    --threads 4 \
    --timeout 180 \
    --graceful-timeout 30 \
    --access-logfile /var/www/comandes-venda-sap/access.log \
    --error-logfile /var/www/comandes-venda-sap/error.log \
    wsgi:app
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
Nota: Gunicorn escoltarà a 127.0.0.1:5002 (només localhost). L'accés extern es fa a través d'Apache, mai directament a Gunicorn. Aquest patró és idèntic al de Kais.
Per què gthread en comptes de sync workers? L'endpoint principal POST /api/afegir-palets/ fa múltiples crides HTTP bloquejants a Service Layer (patró GET-modify-PATCH). Amb 2 sync workers, 3 usuaris B1UP concurrents ja saturarien el pool. Amb gthread 2×4 obtenim 8 slots concurrents amb un footprint de memòria similar. El --timeout 180 deixa marge per crides SL lentes.

Validació: executar bash scripts/smoke_load_test.sh 127.0.0.1:5002 <DocEntry_test> — les 10 peticions concurrents han de tenir temps individual similar al warmup. Si són ~10× el warmup, hi ha un lock (típicament re-login SL); revisar SLClient.
Per què wsgi:app i no app:app? El fitxer wsgi.py és un entry point net per Gunicorn. Actualment només fa from app import app, però permet trampes futures (p.ex. saltar warmup en workers secundaris) sense tocar app.py.

3.4 Recarregar systemd i reiniciar

sudo systemctl daemon-reload
sudo systemctl restart comandes-venda-sap
sudo systemctl status comandes-venda-sap

3.5 Verificar Gunicorn

# Ha de tornar JSON amb "ok":true si la comanda existeix
curl -X POST -s http://127.0.0.1:5002/api/afegir-palets/128

4. Apache VirtualHost (proxy invers)

Els mòduls d'Apache proxy, proxy_http i rewrite ja estaran activats (necessaris per Kais). Només cal afegir el VirtualHost nou.

4.1 Crear el VirtualHost

sudo nano /etc/apache2/sites-available/comandes-venda-sap.conf

Contingut:

<VirtualHost *:80>
    ServerName comandes.agrienergia.local

    # Permetre barres codificades a les URLs (patró consistent amb Kais)
    AllowEncodedSlashes NoDecode

    ProxyPreserveHost On
    ProxyPass / http://127.0.0.1:5002/ nocanon
    ProxyPassReverse / http://127.0.0.1:5002/

    # Servir fitxers estàtics directament (si l'app en té)
    Alias /static/ /var/www/comandes-venda-sap/static/
    <Directory /var/www/comandes-venda-sap/static/>
        Require all granted
        Options -Indexes
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/comandes-venda-sap-error.log
    CustomLog ${APACHE_LOG_DIR}/comandes-venda-sap-access.log combined
</VirtualHost>

4.2 Activar el site i verificar

sudo a2ensite comandes-venda-sap.conf
sudo apachectl configtest
sudo systemctl reload apache2

4.3 Verificar a través d'Apache

# Des del propi servidor
curl -X POST -s -H "Host: comandes.agrienergia.local" \
    http://127.0.0.1/api/afegir-palets/128

5. DNS i tallafocs

5.1 Entrada DNS

Afegir una entrada DNS per comandes.agrienergia.local al servidor DNS corporatiu, apuntant a la IP del servidor:

comandes.agrienergia.local    IN  A    192.168.11.244
Alternativa temporal: Si no es pot modificar el DNS corporatiu, afegir al fitxer /etc/hosts (Linux) o C:\Windows\System32\drivers\etc\hosts (Windows) de cada client SAP Fat Client: 
192.168.11.244  comandes.agrienergia.local

5.2 Tallafocs Ubuntu (UFW)

# Verificar estat (probablement ja Apache està obert per Kais)
sudo ufw status

# Si cal, obrir Apache (port 80)
sudo ufw allow 'Apache'

# NO cal obrir el port 5002 externament — Apache fa proxy
# Si abans es va obrir per proves, tancar-lo:
sudo ufw delete allow 5002/tcp

6. HTTPS (opcional, recomanat)

Per xifrar les crides des dels clients SAP Fat Client cap al servidor Apache (recomanat si la xarxa no és de confiança total), afegir configuració SSL al VirtualHost:

sudo a2enmod ssl
sudo nano /etc/apache2/sites-available/comandes-venda-sap-ssl.conf
<VirtualHost *:443>
    ServerName comandes.agrienergia.local

    SSLEngine on
    SSLCertificateFile      /etc/ssl/certs/agrienergia-local.crt
    SSLCertificateKeyFile   /etc/ssl/private/agrienergia-local.key

    AllowEncodedSlashes NoDecode
    ProxyPreserveHost On
    ProxyPass / http://127.0.0.1:5002/ nocanon
    ProxyPassReverse / http://127.0.0.1:5002/

    ErrorLog ${APACHE_LOG_DIR}/comandes-venda-sap-ssl-error.log
    CustomLog ${APACHE_LOG_DIR}/comandes-venda-sap-ssl-access.log combined
</VirtualHost>
sudo a2ensite comandes-venda-sap-ssl.conf
sudo ufw allow 'Apache Full'
sudo systemctl reload apache2
Si es fa HTTPS, actualitzar també la URL a la UF-038 del B1UP (secció 7) de http:// a https://.

7. Actualitzar el botó B1UP a la nova URL

Un cop Apache serveix l'aplicació, cal actualitzar la URL al codi de la Universal Function UF-038 del B1UP perquè apunti al domini nou (en lloc de http://192.168.11.244:5002/).

7.1 Obrir el codi C# de UF-038

  1. SAP Fat Client → Boyum IT → B1 Usability Package → Configurator.
  2. Anar a Función → Función Universal.
  3. Obrir UF-038 "HTTP Motor Embalatges".

7.2 Canviar la URL

Buscar la línia:

"http://192.168.11.244:5002/api/afegir-palets/" + docEntry

i canviar-la per (segons si es fa HTTP o HTTPS):

// Amb HTTP simple
"http://comandes.agrienergia.local/api/afegir-palets/" + docEntry

// Amb HTTPS
"https://comandes.agrienergia.local/api/afegir-palets/" + docEntry

7.3 Actualitzar i verificar

  1. Clicar Actualizar a B1UP.
  2. Obrir una comanda de venda al SAP Fat Client.
  3. Clicar el botó "Calcular embalatges".
  4. Ha d'aparèixer el missatge d'èxit al StatusBar i les línies palet actualitzades automàticament.
El codi C# complet està versionat al repo a docs/b1up_uf038_calcular_embalatges.cs per poder-lo restaurar si es perd la config B1UP.

9. Manteniment i actualitzacions

9.1 Actualitzar l'aplicació (nova versió al GitHub)

# El script deploy.sh gestiona el git pull, restart i verificació
cd ~
sudo bash /home/ohijazo/deploy.sh
# O si el script no és al home:
sudo bash /var/www/comandes-venda-sap/deploy.sh

L'script:

  • Fa git pull al directori de l'app.
  • Actualitza dependències Python si requirements.txt ha canviat.
  • Reinicia el servei systemd.
  • Verifica que el servei ha arrencat correctament.

9.2 Rollback a una versió anterior

cd /var/www/comandes-venda-sap
sudo -u www-data git log --oneline -10             # llistar commits
sudo -u www-data git reset --hard <hash-commit>    # rollback
sudo systemctl restart comandes-venda-sap

La rotació setmanal la configura automàticament deploy.sh --first-install copiant deploy/logrotate/comandes-venda-sap del repo a /etc/logrotate.d/. També se sincronitza en actualitzacions posteriors si el fitxer del repo canvia.

11. Resolució de problemes

El servei no arrenca

sudo systemctl status comandes-venda-sap
sudo journalctl -u comandes-venda-sap -n 50 --no-pager

Causes freqüents:

  • .env absent o mal format: verificar /var/www/comandes-venda-sap/.env (permisos 640 www-data:www-data).
  • KAIS_APP_PATH incorrecte: el servei ha de tenir Environment=KAIS_APP_PATH=/var/www/comandes-venda. Si Kais està en un altre path, ajustar.
  • Port 5002 ocupat: sudo ss -tlnp | grep 5002.

Apache dona 502 Bad Gateway

Gunicorn no respon. Verificar:

sudo systemctl status comandes-venda-sap
curl -X POST -s http://127.0.0.1:5002/api/afegir-palets/128

L'endpoint respon 502/504 des del botó B1UP

Verificar connectivitat cap a serveis SAP:

# SQL Server SAP
nc -zv AE01SAPSQL.Agrienergia.local 1433

# Service Layer
curl -k -I https://192.168.11.238:50000/b1s/v1/

# Test complet des del servidor
curl -X POST -s http://127.0.0.1:5002/api/afegir-palets/<DocEntry_test>

Service Layer retorna error -1116

Bloqueig conegut del backend SL (cache/procés corrupte). Solució:

# Al servidor Windows on corre SAP B1
Restart-Service b1s50000, b1s50001, b1s50002, B1ServerTools64ServiceLayerController -Force

Detalls: tasks/lessons.md L1 al repo.

El botó B1UP dona error de refresh

Verificar que la comanda estigui desada (fm_OK_MODE). El codi C# ja fa aquesta comprovació i mostra un missatge instructiu si no.
